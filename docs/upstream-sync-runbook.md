# 源仓库更新合并工作流

## 触发与原则

用户在本项目提出“检查源仓库更新并合并进来”等同义请求时，按本文执行到本地合并提交完成。
这是一套按请求执行的流程，不创建定时任务，不自动监控或推送。

源仓库：`https://github.com/xxxscarlxrd404/qq-farm-bot.git`。
默认远程名为 `upstream`，定制仓库为 `origin`，每次以实际配置核实。

**核心准则：不得丢弃本地定制化改动。** 保留本地功能、行为约束、持久化配置、测试、
文档和未提交工作，同时整合上游新增能力。不能只追求消除文本冲突。
若双方行为无法兼容，先说明具体取舍并询问用户，不能静默删除本地功能。

## 1. 检查现场并获取更新

```bash
git status --short --branch
git remote -v
git log -12 --oneline --decorate
```

- 读取当前 `AGENTS.md` 及受影响目录的代理说明。
- 确认当前分支及用户目标；不要擅自切换分支或复用未完成的 merge、rebase、cherry-pick。
- 记录合并前 HEAD、已暂存、未暂存和未跟踪文件，后续仅提交本次同步的文件。
- 未跟踪缓存等无关文件保持不动。已有改动若会与合并或验证互相干扰，先停下来与用户确认
  保存或隔离方式，不自动 stash、清理、覆盖或提交用户工作。
- `upstream` 不存在时可添加上述源仓库；若同名远程指向其他地址，不直接改写，先核实。

```bash
git fetch upstream
git remote show upstream
```

确认源仓库默认分支，当前为 `main`；以下命令以 `upstream/main` 为例，分支改变时相应调整。
获取失败不得用旧远程引用声称已检查最新更新。

## 2. 报告差异并识别定制交集

```bash
git log HEAD..upstream/main --format='%h %ad %s' --date=iso-strict
git rev-list --left-right --count HEAD...upstream/main
git diff --stat HEAD...upstream/main
git log upstream/main..HEAD --oneline
```

向用户简要列出缺失提交及主要内容，区分“缺少上游提交”和“本地独有提交”。
没有缺失提交时不创建空合并提交，直接报告已同步。

阅读上游实际 diff、上次合并的冲突处理和受影响的本地实现及测试，识别双方行为差异。
历史提交标题不能替代代码检查，定制清单也不能视为穷举。

本地定制的典型检查项包括：账号认证与恢复、好友监控和通知、合并农场视图、背包锁定、
仅种植 2x2、种植等级例外、测变异、活动时间与持久化开关保护、共用设置配置和 UI 组件。

## 3. 合并并整合冲突

修改文件前说明将合并哪些变化及如何保留定制。

```bash
git merge --no-ff --no-commit upstream/main
git diff --cc
```

- 使用 merge 保留双方历史，不擅自 rebase、重置分支、强推或清理工作区。
- 冲突逐处对照共同祖先、双方实现和测试，保留本地约束并接入上游功能。
  不用 `-X theirs`、整文件 `--theirs` 或复制上游文件绕过整合。
- 检查自动合并文件是否存在语义冲突，例如新增开关未进入本地共享常量、旧设置页遗漏入口、
  上游校验覆盖本地更严格的保护、状态机或字段类型不一致。
- 新旧设置页复用同一配置字段和显隐规则；新增周期动作须覆盖默认值、类型、归一化、
  调度前置条件、结束后持久化关闭和防回启。
- 不放宽付费资源、账号权限、协议校验及活动边界保护，不将真实账号请求用于验证。
- 手工编辑使用 `apply_patch`，新增或调整测试覆盖实际整合风险，避免无关重构。

## 4. 验证

工作区允许安全运行测试时，执行当前项目脚本；脚本变化后先确认实际定义。

```bash
npm test --prefix core
npm test --prefix web
npm run build --prefix web
git diff --check HEAD
```

当前前端 build 包含 `vue-tsc -b` 类型检查和 Vite 生产构建。
相关素材需核对映射、本地文件和 sha256；活动变化还需检查边界、过期开关、防回启、
手工与自动动作共用校验，以及钻石等付费拒绝逻辑。

检查构建和测试警告，区分已有问题与本次回归。不为通过测试而删除本地定制断言或跳过失败。
验证失败应排查修复；环境阻塞或行为取舍未解决时报告具体状态，不宣称合并已完成。

不自动启动服务或浏览器，不登录或操作真实账号；页面布局、素材裁切和实际交互由用户人工验收。

## 5. 本地提交与交付

- 检查冲突标记、未合并条目、暂存 diff 和文件范围；只暂存本次同步内容，禁止盲目 `git add .`。
- 验证通过后创建合并提交，建议标题 `merge: sync upstream main through <上游短 SHA>`。
- 确认上游目标已成为 HEAD 的祖先、无缺失提交，且原有工作区改动与未跟踪文件仍在。
- 结束前可用 `git ls-remote upstream refs/heads/main` 核对远程分支是否在执行期间继续前进；
  若已变化，明确本次同步到的 SHA，不能声称已包含新出现的提交。
- 交付说明包含原缺失提交、合并提交 SHA、定制兼容处理、验证结果和警告、人工验收项、
  未提交工作保留情况，以及“尚未推送远程”。

用户未明确要求时，不推送远程、不部署或重启服务，不删除原有文件，也不创建定时任务。
